# Bill Formats

TabLedger 解析的四类账单格式与校验规则。所有解析器对**内容**识别来源（magic bytes、表头、内部文字），文件名只是弱信号。

## 支付宝（Alipay）

- 载体：加密 `.zip`（ZipCrypto，导出时设置的解压密码）或明文 `.csv`
- 编码：GB18030
- 结构：前置信息区（含「共 N 笔记录」「收入/支出/不计收支：N 笔 X 元」声明汇总）+ 12 列明细
- 明细列：交易时间、交易分类、交易对方、对方账号、商品说明、收/支、金额、收/付款方式、交易状态、交易订单号、商家订单号、备注
- 校验：
  - 表头必须精确匹配，否则拒绝解析；
  - 声明汇总与明细逐项核对（笔数 + 金额）；「交易关闭」订单造成的口径差会标注，不阻断；
  - 退款记录（状态=退款成功）按交易订单号前缀回链原单。

## 微信支付（WeChat）

- 载体：加密 `.zip` 或明文 `.xlsx`
- 编码：OOXML（UTF-8）
- 结构：前置信息区（第 7–10 行声明汇总）+ 第 18 行表头 + 11 列明细
- 明细列：交易时间、交易类型、交易对方、商品、收/支、金额(元)、支付方式、当前状态、交易单号、商户单号、备注
- 校验：
  - 表头（第 18 行）必须精确匹配；
  - 声明汇总（收入/支出/中性交易 + 共 N 笔）与明细**必须完全一致**，不一致即报错；
  - 交易时间为 Excel 序列号，按 1900 日期系统换算；
  - 退款按「状态含退款 + 同账户 + 金额 + 商户/商品相似度」回链唯一前序原单。

## 工商银行（ICBC）

- 载体：加密或明文 `.pdf`（加水印字体）
- 结构：每页一个 13 列表格；水印使用随机命名的子集字体，按其携带的校验文字识别并整字体过滤
- 表头含「交易日期」，13 列
- 列布局（解析索引）：0 交易日期+时间、6 业务类型、7 交易场所、8 交易金额、9 账户余额、10 对方户名、11 对方账号、12 用途
- 校验：
  - 顺序为时间升序；
  - **余额链**：每行 上一行余额 + 本行发生额 = 本行余额，断裂即中止处理（防错账扩散）；
  - 记录 schema（字段顺序/金额符号/必填列）逐行校验。

## 中国银行（BOC）

- 载体：加密或明文 `.pdf`
- 结构：每页一个 12 列表格，**最新记录在最前**
- 表头含「记账日期」，12 列
- 列布局：0 记账日期、1 记账时间、3 金额、4 账户余额、5 交易类型明细、6 支付方式、7 营业网点、8 附言、9 对方户名、10 对方账号、11 对方开户行
- 校验：
  - 整体**精确反转**为升序（不能用排序替代——同秒交易依赖原始顺序）；
  - 余额链同工行；
  - 对方户名中的换行合并为单行，占位横线清空。

## 通用安全约束

| 约束 | 值 |
|------|-----|
| zip 条目数 | ≤ 8，且必须恰好 1 个数据文件 |
| 解压总大小 | ≤ 64 MB |
| 压缩比 | ≤ 200:1（防 zip 炸弹） |
| 嵌套压缩包 | 拒绝 |
| xlsx 内部流 | ≤ 32 MB；XML 用 defusedxml 解析 |
| PDF 页数 | ≤ 200 |
| 单文件 / 请求 | 默认 100 MB / 200 MB（`TAB_MAX_UPLOAD_MB` 等可调） |
| 记录总数 | ≤ 20000 |

## 添加新银行

1. 在 `app/core/parsers/` 新增解析器，产出与 `SCHEMA_FIELDS` 一致的记录（金额用 `Decimal`）；
2. 在 `archive.py` 注册表头嗅探；
3. 用合成数据（`scripts/make_fixtures.py` 风格）补充 fixture 与单测——**不要**用真实账单做测试数据；
4. 银行卡识别信息（卡尾号等）由用户在设置里配置，不得硬编码。
